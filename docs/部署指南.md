# 部署指南（零服务器，约 20 分钟）

全程只在 GitHub 网页上操作，不需要服务器、域名、数据库。

## 0. 你要准备的东西

- 一个 GitHub 账号（Free 计划就够）
- 建议建一个**组织**（Organization），例如 `lab-weekly`，把老师和学生都拉进来
  - 用组织的好处：学生私有仓库集中在一个 owner 下，汇总脚本一次就能列全
  - 没有组织也能用：改成"老师个人账号 + 每个学生把老师加成 collaborator"，但汇总只能按名单跑（见第 8 节 roster）

## 1. 建学生仓库模板（一次性）

1. 在组织下新建仓库 `weekly-template`，**Private**
2. 把本项目 `student-template/` 里的所有文件（含 `.github/`）上传进去
3. 仓库 `Settings` → 勾选 **Template repository**

学生以后每周的操作就是：`Use this template` → 建 `weekly-<自己的拼音>` → 上传 PPT。

> 不想用模板仓库，也可以让学生手动建私有仓库后把 `student-template` 的内容拷进去。

## 2. 建看板仓库

1. 新建仓库 `lab-weekly`（**必须 Public**，否则 Free 计划无法发布 Pages）
2. 上传本项目的全部文件（`index.html` `css/` `js/` `scripts/` `.github/` `docs/` 等）
   - 网页上传：仓库首页 → `uploading an existing file` → 把整个文件夹拖进去
   - 命令行：`git init && git add . && git commit -m init && git push`

## 3. 生成只读 Token（让 Actions 能读学生的私有仓库）

1. 右上头像 → `Settings` → `Developer settings` → `Personal access tokens` → **Fine-grained tokens** → `Generate new token`
2. 填写：
   - **Resource owner**：选你的组织（这一步很关键，选成个人账号会读不到组织私有仓库）
   - **Expiration**：90 天（到期前记得重新生成并更新 Secret）
   - **Repository access**：`All repositories`
   - **Permissions**：`Contents` → **Read-only**（`Metadata` 会自动只读，其余都不勾）
3. 生成后**立刻复制**（`github_pat_...`，只显示一次）

> 这个 Token 只给 Actions 用，不进浏览器、不进代码仓库。

## 4. 配置仓库变量与密钥

看板仓库 → `Settings` → `Secrets and variables` → `Actions`

**Variables（变量，明文，可见）**

| 名称 | 值 | 说明 |
|---|---|---|
| `ORG` | `lab-weekly` | 组织名或用户名 |
| `REPO_PREFIX` | `weekly-` | 学生仓库前缀 |

**Secrets（密钥）**

| 名称 | 值 |
|---|---|
| `ORG_READ_TOKEN` | 第 3 步的 token |

## 5. 打开 Actions 写权限

`Settings` → `Actions` → `General` → 最下方 **Workflow permissions** → 选 **Read and write permissions** → Save

（汇总后会 `git commit` 一次 `data/summary.json`，需要写权限；提交信息带 `[skip ci]`，不会死循环）

## 6. 打开 Pages

`Settings` → `Pages` → **Build and deployment** → `Source` 选 **GitHub Actions**（不要选 "Deploy from a branch"）

## 7. 跑第一次

1. 仓库顶部 `Actions` → 左侧「汇总并发布看板」→ 右侧 `Run workflow` → `Run workflow`
2. 等 1–3 分钟，两个 job（build / deploy）都变绿
3. 打开 `https://<你的用户名>.github.io/lab-weekly/`
4. 应该能看到提交矩阵；如果显示"没有可读的汇总数据"，看第 9 节排查

之后每周一 09:00（北京时间）自动汇总一次。想随时更新，点一次 `Run workflow` 即可。

## 8. 学生不在同一个组织怎么办（可选）

如果学生用自己的个人账号建仓库，把仓库列表写进仓库根目录的 `roster.json`（格式见 `roster.example.json`）：

```json
[
  { "name": "张三", "login": "zhangsan", "repo": "zhangsan/weekly" },
  { "name": "李四", "login": "lisi", "repo": "lab-weekly/weekly-lisi" }
]
```

然后在 `Settings → Secrets and variables → Actions → Variables` 里加一条 `ROSTER` = `roster.json`（不用改工作流代码）。
此时 `ORG` 可以留空，汇总只按名单跑。

前提是 `ORG_READ_TOKEN` 对这些仓库有 Contents 读权限（把它们加进组织，或在 token 里授权对应仓库）。

## 9. 排查清单

| 现象 | 原因 |
|---|---|
| 页面提示"没有可读的汇总数据" | 还没跑过 workflow，或 `ORG` 变量没配；也可以先打开 `/#demo` 看演示 |
| 汇总里 0 个学生 | `REPO_PREFIX` 和学生仓库名不匹配；或 token 的 Resource owner 选错、Repository access 没包含这些仓库 |
| workflow 最后一步 push 失败（403） | 第 5 步的 Workflow permissions 没开 |
| Pages 打不开 / 404 | `Settings → Pages` 的 Source 不是 `GitHub Actions`，或 deploy job 还没跑完 |
| 显示 "迟交" 但学生说按时交了 | 判定按 push 时间（commit 时间）算；默认周日 23:59，可在页面「设置」里改成"周一 09:00"或不判定 |
| 格子颜色没变化 | 浏览器缓存，强制刷新（Ctrl/Cmd + Shift + R） |

## 10. 关于隐私（请务必读）

- 看板仓库是 public，`data/summary.json` 里默认只有：学生姓名（取自仓库名）、仓库名、文件名、提交时间。**不含** PPT 内容、提交说明、进展正文。
- 如果打开 `INCLUDE_PROGRESS=1` / `INCLUDE_MESSAGE=1`，进展正文会进公开 JSON —— 未发表的研究内容会泄密，课题组请谨慎。
- PPT 原件始终在私有仓库里，谁能看由 GitHub 权限决定：老师点「在 GitHub 打开」用的是自己已登录的会话。

## 11. 可选：页面内直接预览 PPT 文字

不配置也能用（点"在 GitHub 打开"即可）。想让老师在看板里直接读每页文字：

1. 再生成一个 fine-grained token，`Contents: Read-only`，只授权学生仓库
2. 打开看板 → 右上「设置」→ 高级 → 填 Token → 保存

Token 只存在该浏览器 `localStorage`，建议 30–90 天轮换，公共电脑上别用。

## 12. 成本

| 项目 | 额度 | 说明 |
|---|---|---|
| GitHub Pages | 1 GB 站点、100 GB/月流量 | 本项目静态资源 < 100 KB，够用 |
| Actions（public 仓库） | 免费无限 | 看板仓库 public，所以汇总不花钱 |
| Actions（学生私有仓库） | 2000 分钟/月 | 检查工作流每次约 10 秒，可忽略 |
